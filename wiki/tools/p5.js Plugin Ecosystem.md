# p5.js Plugin Ecosystem

A **survey** of the addon / plugin libraries that extend [[p5.js]]. The npm registry shows **165+ packages** with the `p5` keyword (as of 2026-05-17); this page covers the substantive ones — those with active maintenance, real download volume, and genuine added capability.

Adopted as part of an addendum to the [[Research - Algorithmic Composition and Tools Sweep|Algorithmic Composition + Tools sweep]] after a user-flagged audit revealed the plugin ecosystem was scoped in the [[Algorithmic Composition|catalog stub]] but dropped during the depth-dive.

**Not all p5.* libraries are p5.js plugins.** Some (e.g., q5.js) are *sibling libraries* with separate evaluations.

## Categories

### Framework integrations (using p5.js inside another framework)

- **@p5-wrapper/react** (~45k weekly dl) — official React component for embedding p5 sketches. The dominant React ↔ p5 integration. MIT.
- **@p5-wrapper/next** (~14k weekly dl) — Next.js-specific variant. MIT.
- **p5-svelte** (~1k weekly dl) — Svelte 4 component. MIT.
- **svelte-p5** / **svelte-p5-components** — Svelte 5 integration with rune bridge.
- **@58fe/p5** — Vue 3 component (less actively maintained).

**Verdict**: If you're in a React/Next codebase, `@p5-wrapper/react` is the obvious choice — high download volume, active maintenance, MIT license. For Svelte 5, `svelte-p5` is the current best.

### Drawing and brush addons

- **p5.brush** (~1.2k weekly dl) — **Natural brushes**, watercolor effects, flowfields, intuitive hatching. Specifically aimed at generative-art-style brushwork (the "painterly" aesthetic). MIT, actively maintained (latest release within 13 days as of 2026-05-17).
- **p5.scribble** — hand-drawn / sketchy-line rendering style.
- **p5.bezier** — extended bezier-curve operations.

**Verdict**: **p5.brush is the standout** — directly supports the natural-brush generative aesthetic that Tyler-Hobbs-style or watercolor-style work needs. **First-class for priority 1** when the work calls for painterly aesthetics.

### Geometry and collision

- **p5.collide2D** — 2D collision detection (point/rect/circle/line).
- **p5.geometry** — extended geometric primitives.
- **p5.shape** — generative shape primitives.

**Verdict**: All useful but specialized. Reach for them when needed; not core-stack defaults.

### Animation and timing

- **p5.createloop** — animation loops with noise + GIF export, "one line of code." Good for short loopable generative art.
- **p5.func** — extended easing functions / interpolation helpers.

**Verdict**: `p5.createloop` is the standout for Genuary-style daily generative work where GIF output is the deliverable.

### Audio (priority 4 relevance)

- **p5.sound** — official p5.js audio addon (FFT, oscillators, sound playback). Wraps [[Web Audio API and AudioWorklet]] with p5.js ergonomics. *Was bundled with p5.js; now optional.*

**Verdict**: For priority 4 in a p5.js codebase, p5.sound is the natural choice. For non-p5.js codebases, use [[Web Audio API and AudioWorklet]] directly. p5.sound is good ergonomics but limited compared to raw Web Audio for advanced work.

### Games and physics

- **p5.play** (~1.3k weekly dl) — Game engine on p5.js + Box2D physics. Sprites, collision, animations. Substantial library; a real game engine.
- **q5play** — sibling for [[q5.js]] (Box2D physics on WebGPU graphics).

**Verdict**: First-class for game-style work; outside the wiki's four priorities directly but relevant when generative-art crosses into interactive game-like installations.

### Effects and post-processing

- **p5.asciify** — real-time ASCII conversion effect.
- **p5.capture** (~470 weekly dl, 3 dependents) — easy recording of p5.js animations to video/GIF.
- **p5.tree** — render pipeline for p5.js v2 (post-processing pipe, picking, declarative control panels).

**Verdict**: `p5.capture` is broadly useful for **recording priority-1 generative output**; should be in any p5.js artist's toolkit. `p5.tree` is more ambitious but young (v0.0.x).

### Development / project management

- **p5-manager** — CLI for scaffolding p5.js projects.
- **map-number**, **@anselan/maprange** — Processing-style `map()` function as standalone packages (useful outside p5.js too).

**Verdict**: Nice-to-have utilities; not central.

### UI / parameter control

- **guify** — General-purpose JS variable inspector / GUI (tagged for p5 and three.js). Similar role to TweakPane / lil-gui (see [[Creative Coding Utilities]]).

**Verdict**: One option among several in the GUI-panel space; see [[Creative Coding Utilities]] for the comparison.

## Plugins explicitly NOT recommended as defaults

| Plugin | Reason |
|---|---|
| **p5.dom** | Deprecated; functionality merged into p5.js core. |
| **p5.SceneManager** | Useful but less actively maintained; consider state-machine patterns instead. |
| **p5.particle** | Numerous abandoned variants; build particle systems from scratch or use three.js. |
| **p5.gui** (older one) | Superseded by guify and other UI libraries. |

## A recommended p5.js addon stack

For priority-1 generative-art work in a p5.js + React + p5.brush stack:

```
@p5-wrapper/react  (React integration)
  + p5.js          (core)
  + p5.brush       (natural brushwork)
  + p5.capture     (recording output)
  + culori         (perceptual color — see The Color Stack)
```

For priority-4 visualizer work, prefer [[q5.js]] (WebGPU) or [[three.js]] over the p5.js + p5.sound combination — performance ceiling matters more than ergonomics there.

## How this updates the original Tools Map verdict

The [[Tools Map]] gave p5.js the verdict "first-class pedagogical; second-class production." The plugin ecosystem doesn't change this fundamentally, but the **specific addons** can elevate priority-fit:

- p5.brush + p5.capture + @p5-wrapper/react = **first-class for priority 1 static generative art** when the painterly aesthetic is wanted.
- For dynamic / dense work, the performance ceiling of p5.js's Canvas2D / WebGL backends still limits it; consider q5.js or three.js.

## Caveats

- **Plugin maintenance is uneven**. Several p5.* packages on npm haven't been updated in 3+ years and may not work with p5.js v2.
- **Documentation quality varies wildly**. p5.brush and @p5-wrapper/react are well-documented; smaller plugins often have one-paragraph readmes.
- **Plugin incompatibilities**: p5.brush and p5.tree both want to manage rendering pipelines — they may conflict if used together.
- **p5.js v2 is the current major version**; older plugins targeting v1 may need adaptation.

## Connection to the wiki's framework

The p5.js plugin ecosystem **extends the p5.js page's verdict** — first-class pedagogical / second-class production becomes **first-class for several specific generative-art niches** when the right addons are in play. The combination p5.brush + @p5-wrapper/react + p5.capture is a legitimate priority-1 production stack for painterly generative work.

For the recommended-stack pattern in [[Tools Map]] (infrastructure + general-purpose + paradigm-specialist), p5.brush counts as a **paradigm specialist** for the natural-brush / painterly paradigm.
