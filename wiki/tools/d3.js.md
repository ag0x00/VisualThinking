# d3.js

**Data-Driven Documents** (Mike Bostock 2011+). The dominant library for **data visualization in the browser**. Combines a powerful data-binding paradigm with SVG (and increasingly canvas) rendering. Less known: d3.js contains an **extensive collection of modular utilities** — color, geo, shape, scale, hierarchy, force-simulation, contour, Delaunay — many of which are useful **outside** data-vis contexts for general generative work.

**Verdict: first-class for data-driven graphic design** (priority 3) and **second-class for pure generative art** (priority 1) where its functional / mathematical modules earn their place.

## Purpose (one line)

Modular data-visualization library combining declarative data-binding to DOM/SVG, with extensive utilities for scales, geo, shape, contour, hierarchy, force-simulation, and color.

## Rubric scores

### Purpose-fit per priority

| Priority | Score | Why |
|---|---|---|
| 1. Generative art (static + dynamic) | **3 / 5** | The modular utilities (d3-contour, d3-delaunay, d3-force, d3-shape, d3-hierarchy) earn their place even outside data-vis |
| 2. Branding | **2 / 5** | Rarely the right tool for marks; possible for data-driven brand systems |
| 3. Graphic design | **5 / 5** | **Best-in-class** for editorial / interactive data graphics; the dominant tool for data-driven design |
| 4. Music-reactive visualizers | **2 / 5** | SVG-DOM doesn't scale to thousands of elements; use canvas/WebGL alternatives |

### Paradigm coverage

- ✅ **Rule-based / deterministic**: data-driven approach is structurally rule-based.
- ✅ **Stochastic / random-within-rules**: `d3-random` provides distributions; integrates with data flow.
- ✅ **Iterative / dynamical-systems**: `d3-force` is a force-directed iterative simulation for layout (great for organic-looking node-graphs).
- ⚠️ **Evolutionary**: not native; could be built using d3's data-binding.
- ⚠️ **Learning-based**: not the paradigm.

### Autonomy-control fit

**Score: 4 / 5** — d3.js spans the **controlled to middle** region well. Highly-controlled data-vis (specific charts) is its strength; stochastic-rule and iterative work via the utility modules.

### Primitive vocabulary

- ✅ **d3-scale**: scales (linear, log, time, ordinal, quantile, sequential) — the foundation of data mapping. Reusable beyond data-vis for any **parameter mapping**.
- ✅ **d3-color**: color manipulation; **OKLCH support via d3-color v3+**. Same author as culori, similar philosophy.
- ✅ **d3-shape**: arc, area, line, pie, stack, symbol generators — vector primitives for charts and beyond.
- ✅ **d3-hierarchy**: tree layouts (cluster, pack, partition, tree, treemap) — useful for any hierarchical visualization.
- ✅ **d3-force**: force-directed simulation for graph layout and organic positioning.
- ✅ **d3-delaunay**: Delaunay triangulation + Voronoi (overlaps with [[Pts.js]] but more performant).
- ✅ **d3-contour**: contour-line generation from gridded data; useful for many generative-art applications.
- ✅ **d3-geo**: cartographic projections; specialized but rich.
- ✅ **d3-selection**: DOM/SVG manipulation with data-binding.
- ⚠️ No 3D primitives.
- ⚠️ No shaders.

### Idiomaticity and LLM-codegen friendliness

**Score: 5 / 5** — among the most-LLM-friendly libraries:

- **Massive training-data presence** — d3 examples are everywhere on the web.
- **Comprehensive documentation** with examples for every module.
- **Modular ES-imports** mean you import only what you need.
- **TypeScript definitions** for all modules.
- **API is mature and stable** — minor breaking changes between major versions.

### Production-readiness

**Score: 5 / 5** — industry-standard:

- ISC-licensed (very permissive).
- Mature (v1 in 2011; v7 in 2026).
- Bundle size depends on imports — tree-shaking is essential (full d3 is ~300kB but typical use is ~50kB).
- Production usage: New York Times graphics desk, Bloomberg, FiveThirtyEight, hundreds of major data-vis sites.
- Mike Bostock + Observable maintain it actively; documentation and examples on https://observablehq.com/.

## Compared to direct alternatives

| Alternative | When to prefer it |
|---|---|
| **Plotly / Chart.js / Recharts** | Pre-built chart types; less customization but faster delivery. |
| **Vega / Vega-Lite** | Declarative grammar for data-vis; d3 is more imperative / flexible. |
| **Apache ECharts** | Enterprise-style charts; less flexible. |
| **Observable Plot** | Mike Bostock's *new* higher-level library on top of d3. Faster for standard charts; reach for d3 when Plot doesn't fit. |
| **For generative art specifically: paper.js / Pts.js / p5.js** | When data isn't the input or driving force. |

## Use-cases d3.js excels at

- **Data-driven editorial graphics** (NYT-style scrollytelling): the default.
- **Force-directed graph layouts**: d3-force is the dominant tool.
- **Custom chart types**: d3's modularity gives you primitives, not prebuilt charts.
- **Geographic / map visualization**: d3-geo for projections.
- **Treemap, pack, partition layouts**: d3-hierarchy.
- **Color-scale design** (any project): `d3.scaleSequential(d3.interpolateViridis)` and friends.

## Use-cases d3.js is wrong for

- **High-density real-time visualization**: SVG-DOM doesn't scale beyond ~1k elements at 60 fps. Use canvas or WebGL.
- **3D anything**: use three.js.
- **Pure aesthetic generative work without data inputs**: d3 is over-engineered for the use case.
- **Pre-built dashboards**: use Plotly or specialized dashboard tools.

## What's reusable from d3.js outside data-vis

The modular structure means many d3 utilities are useful for **generative art**:

| Module | Use beyond data-vis |
|---|---|
| **d3-scale** | Parameter mappings; smooth domain-to-range transformations |
| **d3-color** | Color-space conversions including OKLCH (use with [[The Color Stack]]) |
| **d3-shape** | Generative line / area / arc / curve generation |
| **d3-delaunay** | Voronoi-based generative compositions |
| **d3-force** | Organic-feeling positioning without manual physics |
| **d3-contour** | Heightmap-to-contour generation; topographic-feel art |
| **d3-hierarchy** | Treemap / circle-pack compositions |

Tree-shake them: `import { scaleLinear } from "d3-scale";`

## Connection to the wiki's framework

d3.js is the **data-driven branch** of the wiki's stack. For priority 3 (graphic design with data input — editorial, infographics, dashboards), it's the default. For priority 1 (pure generative art), d3's utility modules are first-class citizens but you'll typically combine them with paper.js or three.js for rendering.

The wiki's [[Algorithmic Art History|conceptual history]] connects: d3 is the contemporary descendant of the **information-design** tradition (Tufte, Bertin) crossed with the **generative-art** tradition. Edward Tufte's data-ink-ratio principle is a fluency-theory finding (see [[Processing Fluency Theory]]) — d3 enables minimal, high-fluency visualization.
