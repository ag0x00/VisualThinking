## Update (2026-05-20): Subsystem B underway — operator-composition slice shipped

B-via-C resolved into a sharper shape than the 2026-05-17 plan below. **The toolkit IS the operator library**: pure functions over a `RenderPlan` type, half generators (Build), half scorers (Evaluate), sharing one geometric representation. Key reframe (see [[cross-domain-composition]]): **evaluate self-generated render-plans, not bitmaps** — removes the CV/extraction risk, gives higher-information input, enables a deterministic generate→score→optimize loop. Operators measure; profiles set targets.

Shipped on branch `toolkit-screensaver`, **PR #2 (open)** https://github.com/ag0x00/VisualThinking/pull/2. As of end of 2026-05-20 the slice grew to **7 operators**: symmetry · complexity · colorChord · constructionGrammar · lineContinuity · cuerdaSeca · tileComplexity. **2 generators** (`igp` lines, `tiling` cells) + **2 profiles** (`timurid-igp` strapwork = symmetry/complexity/lineContinuity/colorChord; `timurid-tiling` cells = symmetry/constructionGrammar/tileComplexity/cuerdaSeca/colorChord). Composer = weighted mean + ranked fixes. Scorecard gallery (`npm run gallery` → `out/gallery.html`) shows good vs **8 deliberate failures**, each isolating its axis. **53 tests pass, tsc clean.** Spec `docs/superpowers/specs/2026-05-20-operator-composition-slice-design.md` (+ addenda a/b/c/d); plan `docs/superpowers/plans/2026-05-20-operator-composition-slice.md`; `toolkit/README.md` has the scoring-model table.

Patterns established (reuse for every new operator): operator file exports `measure` (target-free) + `scoreAgainst` (returns score + `measured` + `target` + `rule` + optional `components`/sub-bars + `fix`); register in `operators/index.ts`; add to a profile with a target; add a deterministic degraded variant in `src/variants.ts`; probe values via `npx tsx -e` to calibrate the target band/floor; add unit test + acceptance assertion; update README table + spec addendum. Floor target = "higher better" (symmetry, lineContinuity, cuerdaSeca); band = Goldilocks (complexity, tileComplexity, constructionGrammar coverage).

**LOOP CLOSED (2026-05-20).** `improve(generate, params, profile, tuning)` shipped to PR #2 (5 TDD commits on top of the operator slice; **68 tests pass, tsc clean**). The real signature operates on **params, not a plan** (a plan is generator output — can't be improved in isolation): `params → generate → compose → fixes → nudge one knob → regenerate`. A per-generator **tuning map** (`src/tuning/igp.ts`, `tiling.ts`) binds each `fix.axis` to ONE scalar knob `{param,kind,step,min,max,invert?}` — the mirror of how a profile binds operators→targets. `applyNudge` (`src/tuning.ts`) is the pure clamp/step primitive (`<P>` unconstrained, casts internally — declared param interfaces aren't assignable to `Record<string,unknown>`; `as unknown as` needed in tests). The loop (`src/improve.ts`) is **greedy single-knob, revert-and-stop**: each iter acts on the worst-weighted *actionable* fix (has a binding AND not pinned at a bound), regenerates, keeps it only if composite climbed by >1e-4, else stops. Returns `{finalParams, finalPlan, finalScore, trajectory[]}`; each step carries a full params snapshot so `npm run gallery` renders the climb as an "Improvement" group (verified: strapwork lineContinuity→complexity; tilework constructionGrammar×3→cuerdaSeca×4). **Two design lessons worth keeping:** (1) `segmentScale` is a **cliff knob** — continuity is 0 until segments meet at scale 1.0 — so its step is coarse (0.6) to cross the discontinuity in one move; a fine step yields zero gain and trips the revert guard. (2) tuning bounds must be the *real* ceiling (colorCount max=fillCount=3) or a pinned nudge changes the param without changing the plan, fooling the guard. (3) calibration miss: `channelJitter:0.6` does NOT degrade cuerdaSeca (floor met) — the real "uneven channels" degradation is `1.0`. **Deferred (unactionable in v1, those axes simply skipped):** `symmetry` (always p6m — no knob) and `colorChord` (palette is an array; tuning = hue-rotation + lightness-shift, not a scalar). Spec `docs/superpowers/specs/2026-05-20-close-the-loop-design.md`, plan `docs/superpowers/plans/2026-05-20-close-the-loop.md`.

**THIRD MEDIUM — Truchet (2026-05-21): the medium-agnostic spine is PROVEN.** User asked for a wall-to-wall *periodic tessellation* (vs the centered IGP/tiling generators) explicitly to test whether the spine generalizes. It does: adding the medium took **one new operator** + a generator/profile/tuning map; `compose.ts`, `improve.ts`, `tuning.ts`, `profile.ts` and all other operators were **untouched**. The one new operator is **`periodicity`** (`src/operators/periodicity.ts`) — translational lattice self-match: translate `tile` centroids by `plan.symmetry.lattice` vectors and count in-bounds matches. It **replaces** center-rotation `symmetry` for this medium (the coupling the test surfaced: `symmetry` rotates about a center, periodic patterns have *translational* invariance). It matches on cell *frames* only → rotation-blind → varied Truchet still scores ~1.0; only a corrupted lattice drops it. `generateTruchet` (8×8 arc-tile grid; knobs `gridSize/cellScale/latticeJitter/arcGap/arcSteps/rngSeed`) emits one `tile` square + two `kind:"path"` polyline arcs per cell; svg.ts gained a `path`→`<polyline>` (unfilled) branch. Profile `truchet` = periodicity 0.30 + constructionGrammar 0.25 + lineContinuity 0.25 (floor 0.64, calibrated: clean 0.688−0.05) + colorChord 0.20. **84 tests pass, tsc clean**, 11 commits pushed to PR #2. **Cliff-knob lesson reconfirmed & generalized:** both `latticeJitter` and `arcGap` are cliff knobs (any displacement > eps≈1.13px collapses the match/join), so both use a coarse step = max (one move to 0) — derivable from the eps math *without probing*. broken-lattice degrades periodicity AND lineContinuity together (benign — one knob heals both; periodicity's higher weight keeps it the top fix).

**Boundary principle now durable in CLAUDE.md** (§Engineering discipline, added 2026-05-21): toolkit = spine + transferable measurements; operators measure (taste-free), profiles set taste; a measurement is "core" only if its property is *transferable across unrelated mediums* (not single-tradition — cuerda-seca's channel-uniformity counts). Generators lean on prior art (wiki points to it; IGP page now links the Fares d3 code). **Also:** "do not over-engineer — most elegant & minimal" is now a CLAUDE.md rule (user-requested). Applied immediately: the injectable-operator-registry refactor was DEFERRED (no external consumer needs it yet — `periodicity` went into the existing global registry).
