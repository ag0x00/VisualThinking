Every substantive **build** task follows a six-step loop (canonical page: [[Build Working Loop]] at `wiki/meta/Build Working Loop.md`):

1. **Understand** — restate task; place in the 4 priorities.
2. **Consult the wiki FIRST** (mandatory before design) — `wiki_orient` + `wiki_search` (pair them; orient under-surfaces tradition terms), read relevant concept/technique pages, extract operators/principles.
3. **Research the gaps** — targeted web research; **file new wiki pages**.
4. **Work through aesthetics explicitly** — palette, composition (Ma/negative-space), gesture (organic-motion/directed-tension), eval metrics → concrete knobs BEFORE coding.
5. **Build** minimal against targets (ponytail).
6. **Evaluate** (generate→score→improve), feed learnings + pages back to wiki, commit.

**Why:** user formalized this 2026-06-21 after I built the ink demo with every aesthetic call ad-hoc and the wiki never consulted — violating "the wiki is a participant / the workflow is the product." When I finally ran step 2 the wiki immediately supplied the composition + gesture layer I'd improvised.

**How to apply:** if making aesthetic decisions (palette/composition/gesture/pacing) without having opened the wiki, STOP and do step 2. Plan mode hosts steps 1–4; ExitPlanMode gates 5–6.
